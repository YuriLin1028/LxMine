# LxMine PC / HarmonyOS / Android 对齐清单

## 2026-11-24 v1.3.0 全端定案与 Android 架构对齐补充

- **独立页固定式毛玻璃架构（Android 强制）**：废除 Material 3 `ModalBottomSheet` 与独立系统 `Dialog` 窗口；统一经根宿主 `GlassModalHost` 渲染固定式半透毛玻璃 `GlassSurface(tone = GlassTone.Menu, nested = true, floating = true)`，出现后容器位置锁死、内部禁用拉伸过滚（`LocalOverscrollFactory provides null`），彻底消除上滑撞顶抽搐与实心遮罩。锚点菜单统一交由置于其上的 `GlassOverlayHost` 承载。
- **全端「上模糊、下穿透」规范**：主页面、板块详情、评论页与所有大型独立页（播放队列、更多、耳返、音效、批量下载、排序、编辑歌单、切换平台、自定义封面、本地扫描）仅保留顶部悬浮标题区下方的单向渐进模糊（鸿蒙 `linearGradientBlur`；Android `topProgressiveFade` + 轻盈 `TopProgressiveBlur`），**删除主页面底部模糊遮罩**，禁止重度不透明暗膜。
- **滚动坐标 `px → dp` 统一**：Android 首页、曲库拼贴、歌曲列表、下载页、目录结果与设置页向 ViewModel 上报滚动位置和板块锚点前全部除以 `density` 转为 `dp`，快捷胶囊滚动跳转乘回 `density`，与鸿蒙 `px2vp` 语义完全一致。
- **子独立页返回闭环**：`播放队列 → 播放队列排序 / 切换歌曲平台`、`更多 → 音效 / 定时关闭` 统一先收起父独立页并在子页关闭/完成/返回键后自动回到父独立页（`returnSheetAfterSub`），杜绝双层 Sheet 叠罗汉。
- **细节统一**：首页补齐 `forYou` / `bannerCharts` / `topArtists`、长按歌曲卡菜单与底部相似推荐，移除首页与板块页多余的批量下载按钮；歌单顶栏仅保留搜索球（移除重复管理球）；首页快捷胶囊恢复 40dp/16dp/14sp 与窄屏纯图标适配并修复 `chip_*_on.svg` 着色；播放页与设置页「选择动效」统一为锚点式半透毛玻璃滚动菜单；全面引入浅色/深色自适应语义 token（`CARD_SURFACE` / `CHIP_BG` / `INPUT_BG` / `TRACK_BG` / `BORDER_SUBTLE` / `DIVIDER_COLOR`）。
- **多端更新通道与发版次序**：`store-release.json` / `harmony-hap-release.json` / `android-release.json` / `windows-release.json`（及后续苹果端独立分发/更新通道）严格物理隔离；涉及 AGC 邀测更新时须先审过再同步推送 GitHub 与官网（详见仓库根 `AGENTS.md` 十条铁律）。
- **桌面形态双向对齐与后续苹果端规范**：
  - 在三端统一基础上，**鸿蒙 PC（`2in1`）与 Windows 端**必须保持桌面级体验双向对齐（桌面歌词、壁纸模式、宽屏行内操作、右键菜单、桌面音量与窗口化布局，仅操作系统底层专属能力保留合理边界）。
  - 后续开发苹果全生态时按设备形态严格对标鸿蒙：**iOS ↔ 鸿蒙手机、iPadOS ↔ 鸿蒙平板、macOS ↔ 鸿蒙 PC（`2in1`）& Windows**；页面结构、布局、交互、3D 舞台与局域网同步协议完全复用既有基准，**仅将材质与交互控件切换为苹果原生 Liquid Glass（SwiftUI 原生液态玻璃体系）**，严禁擅自改版。

## 2026-11-17 交互与配色补充

- 普通控件按压统一轻微放大至 1.03。Android 13 及以上的折射滑块单独保持原来的 1.45 倍水球，包含导航、开关和进度滑块；Android 12 及以下继续使用普通材质与点击反馈。鸿蒙和 Windows 保持原有沉浸光感材质。
- Android 13 及以上导航水球恢复 20261116 build10 的速度形变范围（横向拉伸、纵向挤压均为 20% 上限）和独立采样层（48dp 高、24dp 上下折射、球内内容放大至 1.2）；不能用普通按钮的 1% 形变或 12dp 折射层替代。保留触点起球、取消手势复位、收起栏无水球，开关沿用当前实现。
- 个人测试包可显式指定 `-Plxmine.privateTestSources=<本机快照>`，仅向构建目录生成含 20 个源的资产，并校验快照 SHA-256。首次运行只补齐缺少的源，保留当前选择与已有数据，删除的源不会每次启动重新加入；普通构建不含该资产。
- Windows 底栏按压时，玻璃、内部文字与图标由同一弹簧围绕底栏中心统一轻微放大至 1.03，禁止子按钮再叠加一次缩放。鼠标移入播放 iframe 后松手也必须完整复位。
- 缓存的非活动歌词 Web 层必须退出原生触摸命中：鸿蒙直接对 Web 使用 Hidden，Android 保持测量尺寸并移出命中区域；不能仅依赖透明度或父层 HitTestMode.None。两种模式切换时清除旧的手动浏览锁定，并立即以当前播放时钟恢复焦点。
- 播放歌词层不再整体使用 0.78 透明度；浅色模式保留颜色色相并提高对比度，光效不能把深色文字再次冲亮，封面上叠浅灰底保证歌词可读。
- 浅色播放页保留封面与场景本身，不叠整屏增白层；歌词以清晰字形与细描边保证对比，停用浅色歌词的弥散光晕与模糊可读层，避免白雾。无动效歌词以焦点行为中心放大到 1.18，上下按距离连续递减，行框位置不随缩放变化。
- 无动效与动效歌词共用字宽进度、原生逐字时序、变色边缘和两段滚动缓动，自动跟随与点击定位使用同一条连续轨迹。无动效保留左对齐，停用粒子、场景互动和音频节拍。换歌、歌词替换与从隐藏状态唤醒时先对齐当前焦点，暂停后的跟随在一个物理像素以内结束，避免亚像素舍入使动画空转。
- 无动效歌词在同一行内复用逐字节点，重复元数据、前后台通知和视口变化不能重建字形或将已唱进度清零；字形首次插入前设置当前填色，焦点切换前后使用相同的行高。
- Android 的原生歌词 WebView 必须直接绘制，不能放进玻璃背景录制层；玻璃仅采样封面背景，避免文字录制重放导致闪烁。缓存 WebView 的歌词上下留白使用有效视口的像素高度，不能依赖可能为零的 `vh`。
- 沉浸控件统一用 280ms 的透明度和轻微位移过渡；Android 保留控件实例到淡出结束后再退出命中，隐藏态不可点击。退出播放详情或重新进入时恢复控件，首页、歌单库、设置页的底栏显隐独立于沉浸状态；隐藏/失焦的歌词层不能提交旧的双指手势。
- 鸿蒙底栏由唯一 `DockLayer` 持续承载，标题材质宿主与共享内容状态分离，进出播放页、搜索或二级页只改变几何，不重建材质节点。进出播放页不得重复调用 `setColorMode`，外观仅在恢复设置或用户更改外观时应用。
- 鸿蒙保留官方材质 `interactive` 和 `lightEffect`，按压只叠加小幅放大；底栏内部操作不再叠加第二次缩放。隐藏导航与沉浸控件必须用 `BLOCK_DESCENDANTS` 退出整棵命中树，`Transparent` 或 `None` 仍允许子节点抢走原生流光事件。音源页的两个动作按钮保留材质上伸空间并关闭默认按压遮罩。
- Windows 材质法线图在 CPU 画布中生成与编码，避免窗口缩放时同步回读 GPU；法线图字节与原有光学参数保持一致，材质和真实输入帧预算继续通过回归门禁验收。
- 聚合搜索按分页抵达顺序追加，已经显示的结果保持顺序。Android 在主线程串行发布结果快照，行键保留歌曲标识与重复次数，提交搜索后清理输入焦点并收起键盘。鸿蒙 LazyForEach 按稳定标识通知插入与更新，Windows 复用同一个列表和已有歌曲行。离开搜索时作废尚未返回的分页。
- 大歌单导入使用有界详情请求和失败重试。网易云只补齐缺失资料，每批最多 100 首、并发最多 3 个请求，保留歌单原始顺序。QQ 按原始条目数推进分页偏移，再按歌曲标识去重。移动端每个成功返回的分页续期空闲超时，导入操作在完整取得分页后保存。协议字段参照 [LX Music 网易云详情](https://github.com/lyswhut/lx-music-desktop/blob/master/src/renderer/utils/musicSdk/wy/musicDetail.js) 和 [QQ 歌单](https://github.com/lyswhut/lx-music-desktop/blob/master/src/renderer/utils/musicSdk/tx/songList.js)。
- 两种歌词模式均支持单指滚动和点击定位，双指只进出沉浸。动效模式允许从歌词范围外开始的单指操作持续旋转场景；歌词文字周围、行间属于歌词区域，两侧保留可触及的场景边缘。手势归属在按下时确定，不能在拖动途中切换。
- 缓存的原生 WebView 必须使用当前可见状态和元数据，Android 活跃层置于缓存隐藏层之上。鸿蒙播放页不再叠加全屏触摸捕获层或竞争 Web 触摸的原生双指 PanGesture。
- 三端播放背景随深色、浅色、系统模式变化。有封面显示模糊封面，无封面使用对应灰色。共用动效层保持透明，内嵌网页与宿主的 color-scheme 必须同步；歌词配色须保持可读性。
- Android 首页搜索框的展开状态直接跟随当前滚动位置，不能被底栏的滚动方向判断、布局抑制期或停止滚动的最后一帧跳过。返回首页时重新同步滚动位置。
- 鸿蒙复用现有首页位置轮询补齐回顶后的搜索框展开，不增加新的几何轮询。关闭“启动时继续播放”时，两种移动端仍需在运行环境就绪后补齐恢复歌曲的歌词与封面；资料加载不得触发音频播放。

## 平台边界

- 桌面歌词：Windows 与鸿蒙 PC（`2in1`）保持桌面级独立悬浮窗双向对齐；Android 手机/平板采用自绘纯文本逐字渐变悬浮窗（独立于播放页的歌词设置项，默认封面取色渐变、支持窗口缩放与自由拖动）；鸿蒙手机/平板走官方 `AVSessionKit` 系统桌面歌词托管（满足应用市场合规要求，颜色、字号与拖动边界由鸿蒙系统控制）。
- Windows 托盘、登录 Windows 后启动、与 Wallpaper Engine 共存的桌面壁纸宿主：依赖 Windows，没有在移动端添加无效开关。
- HiCar、智感握姿：保留移动端专用入口，不加入 PC。
- 四平台匿名内容、聚合／分平台搜索继续保留；不增加登录流程。

## 开发规范（2026-11-14 起，硬性）

- **歌曲列表页统一**：凡展示歌曲集合的列表——首页新歌速递、歌单详情、榜单详情、板块更多页、
  搜索歌曲结果、本地音乐、下载列表——PC 一律调用唯一 `songRow`（`songListCard` 只是装载器），
  移动端一律使用 `SongRow` 组件；**禁止自造第二种歌曲行样式**
  （`searchSongRow`、`search-row` 歌曲行、feed-song-row、FeedSectionPage 私有 songRow 均已删除）。
  封面卡片网格（`songCard` / `playlistCard`）只用于横排封面场景（首页横排行、更多页歌单卡片），不得用于歌曲列表。
- **歌曲列表容器透明**：PC 容器统一 `div.song-list`，**禁止 `.list-card` 大圆角背景框**；
  首页新歌速递、搜索、歌单/榜单详情、更多页、本地音乐、下载列表的行必须直接落在页面背景上，
  材质/圆角/悬停反馈由 `.song-row` 自己承担。行结构、48px 封面、36px 操作钮、字号与间距全场景一致。
- **PC 行操作按窗口宽度切换**：`@media (min-width:760px)` 行内直接显示下载/爱心/加号，隐藏展开箭头；

### 首页滚动性能（2026-11-14 定案，硬性）

- **爬取结果不得在滚动中整表替换**：`refreshHomeFeed` 只把结果交给 `queueHomeFeed`，由
  `applyPendingHomeFeed` 在 `now - lastHomeScrollAt > 650ms` 且不在板块/歌单/搜索/播放页时
  才写 `homeFeed`。连续下滑期间爬取完成的首页数据必须挂起，不能重建整棵首页树。
- **首页换数据禁止包 `animateTo`**：`homeFeed` 是整页多板块状态，套弹簧动画会把所有板块
  一起纳入布局动画，直接 swap。首屏无旧内容（`homeFeed == null`）时可直接回填。
- **内容签名去抖**：替换前用 `homeFeedSignature` 比较板块/条目 id、count 与歌曲 id；
  完全一致时只更新缓存、跳过重建。播放量、封面 URL 等纯文字变化不得触发整页重建。
- **大对象序列化延后**：`JSON.stringify(feed)` 与 `saveHomeCache` 必须放在真正应用刷新结果的
  空闲时机；禁止在爬取 Promise 刚完成的瞬间在 UI 线程序列化几百 KB 的首页 JSON。
- **刷新去重**：启动期 `initialize` 与 Web `onPageEnd` 都会触发刷新，必须用 `homeFeedRefreshing`
  防止两路爬取/解析同时进行；双击标题刷新用 `force=true` 允许打断。
- **滚动路径禁止写无用 @State**：`homeScroll`/`onDidScroll` 只允许写普通字段（如
  `lastHomeScrollAt`）；历史遗留的 `homeScrollY` 这类“只赋值不读取”的 @State 必须删除，
  否则每帧都会触发无意义重建。
- **胶囊几何轮询暂停**：300ms 的 `getRectangleById` 高亮维护只在一级发现页执行；
  `feedSection`/`openedPlaylist`/播放页盖住首页时必须暂停。
- **播放进度状态节流**：`timeUpdate` 不得每次都写 `positionMs` @State。一级页/列表页按 1s、
  播放详情页按 200ms 刷新；否则首页滚动/搜索列表会被每秒多次整页重建拖出掉帧。
  `duration` 仅在变化时写；打开播放详情时重置节流时间戳，保证首帧进度立即更新。
- **播放快照禁止反复序列化大队列**：接续内存槽只存 `song/queue/positionMs/playing` 的对象引用，
  系统 `onContinue` 真正调用时才 `JSON.stringify`；持久化快照的歌曲/队列 JSON 必须按引用缓存，
  只有队列或当前歌曲变化时才重新序列化。磁盘快照 15s 一次，并在暂停、切歌、退后台、退出时强制落盘。
  禁止每 1s/5s 对整条队列做 `JSON.stringify`（大歌单会产生周期性掉帧）。
- **验收**：冷启动先显示缓存首页；连续下滑 3s 期间爬取结果返回不得出现整表替换/跳帧；
  停止滚动后才允许应用；日志可核对 `[HomeFeed] refresh unchanged; skip rebuild` 与
  `[HomeFeed] apply refreshed feed`。播放中连续下滑时，进度环/歌词允许按 1s 粒度更新，
  但不得因 `timeUpdate` 每秒多次重建首页。
- **验收清单**：在平板 wide 与手机竖屏分别进入 播放详情 / 搜索 / 飙升榜详情 / 每周新歌详情 /
  下载 / 音源 / 评论，测量返回球 `bounds` 顶边必须同为 `statusInset + 6vp`；球顶不得被裁平；
  长按/拖动球体时图标随球缩放、光感跟随；标题超长单行省略；子页右侧不得出现歌单库三球。
- **PC 对照**：PC 端 `setHeader`（42px 圆钮 / 30px 标题）已是唯一顶栏，仍由 `#page-title` 与
  `#header-actions` 统一承载；不得为某个二级页单独写头部。HarmonyOS 侧新增页面必须复用
  `PageHeader`，不允许再出现第三种顶栏。
