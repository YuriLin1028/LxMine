# 验收协议：真机像素、局部结构、动效与发布门禁

“看起来像”不是验收。本标准要求：同一背景下真机与 PC 的逐像素比较、局部
结构指标、负对照、动效相位、帧预算，以及源码/基准/报告的哈希绑定。

本文给出可复现的协议。参考数值来自 LxMine 项目（PLA-AL10，DPR 3.5，
暗色主题，EXQUISITE），**不是**对所有设备/GPU 的普适常数。新项目必须重新
采集自己的基准。

---

## 1. 证据目录

建议结构：

```
qa/
├─ references/                 # 不可变真机基准（原图 + on/off/repeat）
│  ├─ grid/
│  ├─ type/
│  ├─ grid-tiers/
│  ├─ type-tiers/
│  └─ system-menu/
├─ artifacts/
│  ├─ approved.json            # 通过报告（哈希绑定）
│  ├─ runs/                    # 每次运行的原图/差异图/JSON
│  ├─ comparison-*.png         # 真机 / PC / 4x 差异三联图
│  └─ journal.jsonl            # 参数实验记录
├─ compare.cjs
├─ motion.cjs
├─ system-menu.cjs
├─ popup-motion.cjs
├─ check.cjs
└─ README.md
```

要求：

- `references/` 只增不改；替换必须保留旧文件并记录原因；
- 每次运行保留 PC 原图、差异图、JSON；
- 失败报告不得删除；
- 报告中的哈希覆盖源码、基准、验证器；
- 打包前校验报告，源码变更后旧批准失效。

## 2. 真机基准采集

### 2.1 环境

- 固定设备型号、系统版本、主题（暗色）、字体缩放；
- 固定 DPR（参考 3.5）；
- 关闭自动亮度/护眼模式/色彩滤镜；
- 清理通知和状态栏干扰；
- 同一角度、同一距离、同一曝光。

### 2.2 场景

至少两组背景：

1. **网格**：高对比水平/垂直线条，用于测量位移方向、肩部弯曲；
2. **文字**：带大字号/多行文字的高对比背景，用于测量可读区域和边缘污染。

每个场景包含：

- 52 / 72 高胶囊；
- 64 圆球；
- 28 圆角面板；
- 42 小圆按钮；
- THIN 菜单；
- THICK 弹层。

合计 16 个样本。系统 Select/Menu 另做 6 个场景，使用生产组件。

### 2.3 开/关/重复

每个样本拍：

1. 材质开（on）；
2. 材质关（off）；
3. 再次开（repeat）。

用途：

- `off` 用于 PC 背景对齐；
- `repeat` 验证拍摄稳定性（参考要求重复差 < 1/255）；
- `on` 是目标图。

### 2.4 边界

- 从 UI 树或像素边缘测控件矩形；
- 边界误差 < 0.25 物理像素；
- PC 端用同一 `off` 图、同一 DPR、同一 UI 树渲染；
- 不能平移/缩放成品图来凑分。

## 3. 像素比较

### 3.1 对齐

1. 用 `off` 图确认 PC 背景与真机逐像素一致（< 0.5/255）；
2. 对齐 UI 边界；
3. 以控件矩形外扩 16 CSS px 作为分析区域；
4. 最外 1 CSS px 单独计算 `outlineMAE`，但**仍纳入**全内部门槛；
5. 不在差异图中裁掉不利区域。

### 3.2 指标

| 指标 | 定义 | 参考阈值 |
| --- | --- | --- |
| `allInsideMAE` | 控件内部全部像素（含最外 1px） | ≤ 8/255 |
| `mae` | 材质主体（排除文字/图标区域） | ≤ 8/255 |
| `rimMAE` | 距边 1–10 CSS px 折射带 | ≤ 12/255 |
| `centreMAE` | 中心可读区域 | ≤ 8/255 |
| `outsideMAE` | 外部 16px 阴影带 | ≤ 6/255 |
| `SSIM` | 主体结构相似度 | ≥ 0.92 |
| `outlineMAE` | 最外 1px | 单独报告，不设独立放行 |
| 背景对齐 | `off` 图差 | < 0.5/255 |
| 真机重复 | on vs repeat | < 1/255 |
| 边界偏差 | 物理像素 | < 0.25 |

### 3.3 负对照

必须包含至少一个“关闭折射”的负对照：

- 只保留模糊/透色，不做法线位移；
- 该实现必须被门禁拒绝；
- 如果负对照通过，说明阈值或区域选择失效。

### 3.4 局部结构

全局 MAE/SSIM 会掩盖局部错误，必须额外做：

**球面平滑度**

- 在球体内部取 Laplacian（二阶差分）；
- 计算 PC 与真机的 Laplacian 能量比；
- 参考门禁 ≤ 1.5；LxMine 最终 1.215–1.289；
- 比例过高说明 8 位等值线台阶，增大 `resultSigma`，而不是降低分辨率。

**胶囊肩部**

- 用水平网格背景；
- 测量胶囊上下沿的相位/弯曲曲线；
- 参考最大误差 ≤ 0.75 CSS px（实测 0.375）；
- 文字背景没有稳定水平条纹，不用于该项。

**系统菜单**

- 使用真实生产 Select/Menu，不用 MenuItem 勾选文本冒充；
- 正文区域按原生 UI Text 节点矩形外扩 1 CSS px 排除；
- 选中行用准确原生边界单独统计，要求 MAE ≤ 8；
- 六场景全部存在，缺一失败；
- 重复帧稳定、关闭材质背景完全一致；
- 旧菜单材质负对照必须被拒绝。

### 3.5 结果解释

- SSIM 不是“复刻完成百分比”；
- 通过门禁不等于逐像素完全一致；
- 最外 1px 抗锯齿轮廓仍可能有 14–36/255 的平均差，必须如实报告；
- 声明必须限定设备、主题、场景、DPR、测试机。

## 4. 动效验收

### 4.1 静态相位

- 真实点击生产弹窗；
- 用 CDP/动画时间轴暂停到固定相位；
- 截图；
- 与原生录屏注册标题位置和缩放；
- 模板匹配置信度 < .82 只报告，不作精度断言；
- 缩放差 ≤ .025，横向 ≤ 5 CSS px，纵向 ≤ 3 CSS px。

### 4.2 实时帧预算

- 真实合成窗口、DPR 1、关闭后台节流；
- 每项场景独立 Electron 进程、隔离用户目录；
- 预热：完整打开/关闭/滚动一轮；
- 采样 120+ 帧，计算 P95 / max；
- `PerformanceObserver('longtask')` 记录 >50ms；
- 阈值：P95 < 33.5ms，max < 50ms，长任务 0；
- 固定相位截图不能替代实时帧预算。

### 4.3 场景

至少：

1. 指针拖动 + 回弹 + 离开复位；
2. 播放页进入/退出；
3. 长菜单连续开合；
4. 窗口 resize 到 420/540/800/1200 等宽度；
5. 搜索形变；
6. 队列/模态开合。

### 4.4 冷却

场景之间保留冷却（参考 20s）。原因：Electron/GPU 合成器异步销毁可能让下一个
场景捕获到 56–75ms 的假尖峰。不要把冷却当成“掩盖问题”：如果单场景独立运行
仍超标，必须修。

### 4.5 文本稳定性

在按压/拖动时比较文字区域像素差，要求 < 1/255。若文字移动，说明变换了宿主
而不是皮肤。

## 5. 源码与批准绑定

`approved.json` 至少包含：

```json
{
  "status": "PASS",
  "capturedAt": "2026-…",
  "thresholds": { "mae": 8, "allInsideMAE": 8, "rimMAE": 12, "centreMAE": 8, "outsideMAE": 6, "ssim": 0.92 },
  "pixels": [ … 16 samples … ],
  "negativeControlPassed": true,
  "motion": { "p95": 6.3, "max": 31.3, "longTasks": [] },
  "hashes": { "src/hx-material.js": "sha256…", "references/…": "sha256…" }
}
```

发布脚本（Electron Builder `beforePack` 或 CI）：

1. 读取批准报告；
2. `status === PASS`；
3. 样本数 = 16；
4. 所有阈值通过；
5. 负对照被拒绝；
6. 源码/基准/验证器哈希与报告一致；
7. 动效 P95/max/长任务通过；
8. 否则拒绝打包。

要求：

- 测试开始即撤销旧批准；
- 源码/基准/验证器任一变化 → 旧批准失效；
- 不允许手工把 `status` 改成 PASS；
- 不允许用候选参数覆盖生成批准；
- 打包后对实际 exe 再跑 smoke/motion。

## 6. 参考实现结果

LxMine 最终默认源码（限定于该设备/场景/测试机）：

- 16/16 样本通过；
- 全内部 MAE 1.27–7.48/255；
- 折射带最高 11.02/255；
- 外部阴影最高 1.67/255；
- 主体 SSIM 0.949–0.991；
- 最外 1px 轮廓 14–36/255（单独报告）；
- 球面 Laplacian 比 1.215–1.289；
- 胶囊肩部最大相位误差 0.375 CSS px；
- 拖动/弹窗/缩放 P95 约 6.3ms，最大 6.4/18.8/12.6ms，长任务 0；
- 打包后复测 P95 6.3ms、最大 31.3ms、长任务 0。

这些数字用于说明协议可执行，不是让你直接复制阈值或宣称同等结果。

## 7. 新项目落地步骤

1. 选一台真机，固定环境；
2. 生成网格/文字背景；
3. 用原生组件拍 on/off/repeat；
4. 用同一 off 图在 PC 渲染，对齐边界；
5. 先调几何，再调材质；
6. 每次只改一个参数，记录 `journal.jsonl`；
7. 同时看 MAE/SSIM/局部指标；
8. 加入关闭折射负对照；
9. 跑动效/帧预算；
10. 生成批准报告，绑定哈希；
11. 在打包配置中接入 `beforePack`；
12. 打包后复测并归档证据。

## 8. 伦理与声明

- 不声称还原了华为闭源引擎；
- 不把静态分析/公开实现当作二进制算法证据；
- 不删除失败样本；
- 不修改基准/阈值来“通过”；
- 报告限定设备、主题、场景、DPR、测试机和日期；
- 不把 SSIM 当作完成度百分比；
- 不把一次通过当作所有 GPU/所有背景的保证。
